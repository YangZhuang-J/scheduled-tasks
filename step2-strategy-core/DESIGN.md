# 通用化设计（已定稿 v1）

> 核心原则：**客观的「市场状态」与主观的「个人动作」彻底解耦。**
> 市场状态人人共享，个人动作完全个性化。

## 三层架构

```
① 因子层   估值因子(PE/PB分位) → 计算
② 状态层   因子 → N 档离散状态（N 与边界可配，不写死）
③ 动作层   状态 → 买入动作 / 卖出阶梯（完全个性化）
```

## 配置结构（单文件，名字简单）

文件名 `config.json`（需要多套就 `config1.json`、`config2.json`…，名字自定）。

```json
{
  "name": "default",

  "buy_states": [
    {"range": [0, 33],  "freq": "daily",    "amount": 10},
    {"range": [33, 67], "freq": "weekly",   "amount": 10},
    {"range": [67, 100], "freq": "biweekly", "amount": 0}
  ],

  "sell": {
    "min_valuation_pct": 70,
    "ladder": [
      {"profit": 20, "ratio": 0.25},
      {"profit": 30, "ratio": 0.25},
      {"profit": 50, "ratio": 0.5}
    ]
  }
}
```

## 各部分说明

### 买入 `buy_states`（N 档，边界可配）

- `range`：估值分位区间（左闭右开），N 档随意（3档/4档/5档…）
- `freq`：频率，取值 `daily` / `weekly` / `biweekly` / `monthly`
- `amount`：金额，`0` 即停买
- 例：频率变金额不变（每日10/每周10/双周10）、金额变频率不变（每月100/50/10）都能表达

### 卖出 `sell`（高估值闸门 + 盈利阶梯）

- `min_valuation_pct`：估值分位 ≥ 该值才"允许"卖出（高估值闸门）
- `ladder`：盈利阶梯，每级 `profit`（持仓收益率%）→ `ratio`（卖出当前持仓的比例）
- 例：赚 20% 卖 1/4 → 赚 30% 再卖 1/4 → 赚 50% 卖 1/2
- 两级都是使用者设定，不硬编码；暂不支持其他触发方式（回撤止盈等）

**两种卖出模型（用一个参数表达）：**

| 模型 | 配置 | 适用 |
|---|---|---|
| 模型1：估值闸门 + 盈利 | `min_valuation_pct: 70` | A股宽基（均值回归，别低位贱卖）|
| 模型2：纯盈利止盈 | `min_valuation_pct: 0` | 美股长牛 / 想"赚够就走"的人 |

> `min_valuation_pct: 0` 语义 = 任何时候都允许卖 = 关闭估值闸门。默认 70。

### 实现细节备忘（非配置项）

- 卖出阶梯每级**只触发一次**（需记录已触发的阶梯，避免重复卖）
- 持仓收益率 = 当前市值 / 累计投入 − 1
- 频率的"每日/每周/双周/每月"需映射到交易日历执行

## 已确认的决策

1. ✅ 状态数量：可配 N 档，提供预设模板（3档/5档）
2. ✅ 买入动作：频率 × 金额 双维度自由
3. ✅ 卖出：估值闸门 + 盈利阶梯，简单，不加其他触发
4. ✅ 配置载体：单个 `config.json`，名字简单，可多份切换
5. ✅ 收益率口径：**持仓收益率**（卖出时成本基数按比例下调，卖出不改变收益率）
6. ✅ 阶梯重触发：**方案 B**（每级独立：升破门槛触发、跌破该门槛重新武装）——回测验证 A≈失效，B 总收益率 35.2% vs 28.3%
